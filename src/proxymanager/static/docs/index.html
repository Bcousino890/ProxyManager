ProxyManager API

API HTTP para obtener páginas web desde un servicio gestionado: una sola llamada a /scrape devuelve el estado, las cabeceras y el cuerpo de la respuesta, con validación del contenido, sesiones con cookies persistentes y enrutado opcional por un catálogo de proxies propio.

Abrir la consola

Introducción

ProxyManager hace la petición por ti desde nuestra infraestructura y te devuelve un resultado validado: no basta con un HTTP 200. Una respuesta solo se marca como correcta si el código es 2xx, no contiene marcadores de desafío (CAPTCHA, página de bloqueo) y, si lo indicas, incluye el texto que esperabas. Solo las respuestas validadas consumen créditos.

  • Una URL, una llamada: POST /scrape con JSON.
  • Sesiones: cookies cifradas y aisladas por cuenta, reutilizables entre llamadas.
  • Proxies: enrutado opcional por país mediante el catálogo del servicio.
  • Control de gasto: varias claves por cuenta, cada una con límite propio de créditos.

Inicio rápido

  1. Crea una cuenta en la consola. Se incluyen créditos de prueba y una clave por defecto: cópiala al crearla, no se vuelve a mostrar completa.
  2. Llama a la API con la clave en la cabecera x-api-key:
curl -X POST 'https://TU-DOMINIO/scrape' \
  -H 'x-api-key: TU_CLAVE_API' \
  -H 'content-type: application/json' \
  -d '{"url":"https://example.com/","method":"GET"}'

Cambia TU-DOMINIO por el dominio donde se aloja este servicio (el mismo que ves en la barra de direcciones).

Autenticación

Envía tu clave en la cabecera x-api-key. Las claves empiezan por pm_live_. Se guardan únicamente como hash SHA-256, de modo que ni el servicio puede recuperarlas: si pierdes una, revócala y crea otra. Usa una clave por entorno (desarrollo, producción, CI) y mantenlas solo en el servidor, nunca en código de navegador o aplicaciones móviles.

Sin clave o con una clave inválida/revocada, la API responde 401.

POST /scrape

Cuerpo JSON:

CampoTipoDescripción
urlstring, obligatorioURL https en el puerto 443, sin usuario/contraseña ni fragmento. Debe resolver a una dirección pública.
methodstringGET (por defecto), POST, PUT, PATCH, DELETE o HEAD.
headersobjetoCabeceras de la petición saliente. Máximo 30 y 8 KB. Se ignoran Host, Content-Length, Proxy-Authorization y otras cabeceras de conexión.
bodystringCuerpo de la petición (hasta 1 MB).
expected_textstringTexto que debe aparecer en la respuesta para considerarla correcta.
session_idstringSesión creada con POST /v1/sessions. Ver Sesiones.
use_proxyboolEnruta por un proxy del catálogo.
countrystring (2)Código de país del proxy, p. ej. ES. Implica use_proxy.

Las redirecciones no se siguen: recibes el 3xx y su cabecera Location y decides tú.

Respuesta y definición de éxito

{
  "request_id": "req_9c1e…",
  "session_id": null,
  "success": true,
  "status_code": 200,
  "content_type": "text/html; charset=utf-8",
  "duration_ms": 412.7,
  "bytes_transferred": 18342,
  "credits_charged": 1,
  "validation": { "content_expected": true, "challenge_detected": false },
  "headers": { "content-type": "text/html; charset=utf-8" },
  "html": "<!doctype html>…"
}

El propio /scrape responde 200 cuando procesó tu petición; el resultado del destino está en status_code y success.

success es true solo si se cumplen las tres condiciones: (1) el destino respondió 2xx, (2) expected_text aparece en el cuerpo (si lo indicaste, o si el administrador fijó uno global) y (3) no se detectó ningún marcador de desafío.

La detección de desafíos es una heurística de texto (busca términos como «captcha» o «device check»). Puede dar falsos positivos en páginas que simplemente mencionen esas palabras: en ese caso la respuesta llega igualmente con html y validation.challenge_detected = true, y no se cobra. Usa expected_text para afinar.

bytes_transferred mide los bytes de contenido recibidos, no el tráfico de red comprimido. Los errores de transporte (DNS, conexión, tiempo agotado) devuelven success: false y un objeto error. El cuerpo se limita al tamaño máximo configurado; si lo supera, la API devuelve 502.

Sesiones y cookies

Una sesión agrupa cookies entre varias llamadas, por ejemplo para un flujo de inicio de sesión sobre un sitio donde tienes cuenta y autorización.

# 1) crear sesión (caduca a la hora por defecto)
curl -X POST https://TU-DOMINIO/v1/sessions -H 'x-api-key: TU_CLAVE_API'
# → {"session_id":"ses_…","created_at":…,"expires_at":…}

# 2) usarla
curl -X POST https://TU-DOMINIO/scrape -H 'x-api-key: TU_CLAVE_API' -H 'content-type: application/json' \
  -d '{"url":"https://example.com/login","session_id":"ses_…"}'

# 3) borrarla (purga sus cookies)
curl -X DELETE https://TU-DOMINIO/v1/sessions/ses_… -H 'x-api-key: TU_CLAVE_API'
  • Los valores de Set-Cookie se guardan cifrados y no se devuelven en las respuestas.
  • Se reenvían solo a los hosts, rutas y esquemas que el atributo Domain/Path/Secure permite; Max-Age=0 o una fecha pasada la eliminan.
  • Una sesión pertenece a tu cuenta: otra cuenta recibe 404 al usar tu session_id.
  • Tener una cookie no garantiza que el servidor la acepte indefinidamente: puede caducar o invalidarla en cualquier momento.

Proxies y país

use_proxy: true o country enrutan la petición por un proxy HTTP del catálogo del servicio (elegido al azar entre los que cumplan el país). El túnel se abre hacia la IP pública ya comprobada del destino y el certificado TLS se verifica contra el nombre original. Si no hay ningún proxy disponible para la petición recibes 422.

El tipo de red de cada proxy (ISP, residencial, centro de datos) y su país se publican tal como los verificó el administrador; hasta que se verifiquen figuran como desconocidos. No se ofrece rotación para esquivar límites o bloqueos de terceros.

Créditos y facturación

ConceptoCoste
Solicitud directa validada1 crédito (configurable por el administrador)
Solicitud validada por proxy2 créditos (configurable)
Solicitud no validada (desafío, error, contenido distinto)0 créditos

Si no quedan créditos, la API responde 402. Puedes fijar un límite de créditos por clave en la consola para evitar que un entorno agote la cuenta; al alcanzarlo, esa clave recibe 402. El consumo detallado se ve en Uso. Las recargas las gestiona el administrador del servicio (todavía no hay pasarela de pago en línea).

Límites

Ejemplos

Python

import requests

r = requests.post(
    "https://TU-DOMINIO/scrape",
    headers={"x-api-key": "TU_CLAVE_API"},
    json={"url": "https://example.com/", "expected_text": "Example Domain"},
    timeout=60,
)
data = r.json()
if data["success"]:
    print(data["html"][:200])
else:
    print("no validado:", data["status_code"], data["validation"])

Node.js

const res = await fetch("https://TU-DOMINIO/scrape", {
  method: "POST",
  headers: { "x-api-key": process.env.PROXYMANAGER_API_KEY, "content-type": "application/json" },
  body: JSON.stringify({ url: "https://example.com/", country: "ES" }),
});
const data = await res.json();
console.log(data.success, data.status_code);

POST con cuerpo y cabeceras

curl -X POST https://TU-DOMINIO/scrape -H 'x-api-key: TU_CLAVE_API' -H 'content-type: application/json' \

Uso aceptable

Al usar la API aceptas hacerlo solo contra sitios propios o sobre los que tengas autorización, respetando sus condiciones, robots.txt y límites. Queda prohibido: acceder a datos personales o cuentas ajenas, saturar destinos, usar el servicio para eludir controles de acceso o medidas de seguridad de terceros, o atacar redes privadas. El servicio rechaza direcciones privadas o reservadas y puede bloquear destinos y suspender claves que incumplan esta política.

Qué no hace

  • No resuelve CAPTCHA ni supera sistemas antibot. Detecta marcadores de desafío y lo informa en validation; no se cobra esa solicitud.
  • No renderiza JavaScript ni abre un navegador: es un cliente HTTP.
  • No sigue redirecciones automáticamente.
  • No garantiza disponibilidad contractual: el servicio es nuevo y no tiene aún un historial de operación publicado.
